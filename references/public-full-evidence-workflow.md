# 公开全证据审阅工作流

本文件规定外部用户安装 Skill 后即可运行的默认产业园区审阅路径。它把公开行业问题先验、框架先行、完整问题台账、当前网络证据核验和有限的新观点生成组合为一个可移植工作流。

这是一种 **F-style 公开高级运行模式**：它复用正式 F 组“先形成阅读结构，再读稿审阅，并把发现线索与证据分开”的组织思路，但不等同于 [ABCDEF-v1.1 协议](evaluation-groups-v1.1.md)中的正式 F 组。正式 F 还要求冻结的私有 `PriorQuestionManifest`、与 D 相同的 `ExperienceSupportBundle`、严格的读稿前时间链和固定实验条件；缺少任一项都不得将公开运行结果标为 F 组实验结果。

## 默认何时启用

当用户要求审阅、核验、质检、评估或改进一篇产业园区/产业招商/园区投融资/产业服务研究稿时，默认启用本流程，除非用户明确要求：

- 只改文风或排版；
- 只做本地离线审阅；
- 只运行正式 A–F 中的某一个受控实验组；
- 不允许联网或外部检索。

用户请求“审稿”“看看有没有问题”时，若宿主提供网络工具，即视为允许在审阅范围内用最小化、非逐字的检索词查询公开网页。普通公开检索和打开原始来源无需在完成 V1 后再次暂停征求确认；但不得把未公开原文片段、非公开主体、私有 URL、批注或附件字节发送给搜索或其他外部服务。确需传输这些内容，以及使用付费数据库、登录态资源、私有文件、联系专家或对外发送消息时，仍须获得相应的明确授权。

## 输入和时间边界

### 草稿尚未进入审阅上下文

若可以在打开草稿前工作，按以下顺序执行：

```text
任务元数据与中性 topic brief
  -> 读取公开产业园区问题先验
  -> 形成语义阅读框架
  -> 冻结框架或至少记录框架版本
  -> 接收并绑定草稿
  -> 主张拆分、问题发现与联网核验
```

该路径可以描述为“框架先于本次草稿形成”。若需要证明严格 precommit，仍须使用 [读稿前阅读框架](reading-framework-workflow.md)中的哈希、时间和隔离机制。

### 草稿已经出现在对话或提示中

模型不能把已经看到的内容“忘掉”。此时仍先输出一份内部语义框架，再依据该框架进行正式审阅，但必须记录同一套对象：

```json
{
  "runtime": {"precommit_possible": false},
  "framework_timing": {
    "status": "retrospective_framework_first_pass",
    "draft_seen_before_framework": true,
    "causal_claim_allowed": false,
    "framework_artifact_ref": null
  }
}
```

这种方式能够改善生产审阅的覆盖和组织，但不能用于证明“知识在读稿前造成了增量”。不得把事后框架改写成事前框架，也不得补造时间戳或哈希。

## 第一阶段：形成阅读框架

先读取 [产业园区决策研究框架](industrial-park-lens.md)和 [公开产业园区问题先验](public-industrial-park-priors.md)，然后形成不包含 verdict 的内部框架。至少覆盖：

- 中性研究问题、目标读者和将被改变的决策；
- 主要参与方、权力、资源、收益、成本和失败承担者；
- 核心变量的定义、单位、期间、分母、比较基准和生命周期阶段；
- 从政策与要素、空间产品、招商集聚、运营服务到企业和资产结果的机制链；
- 至少一个有竞争力的替代解释、一个反例方向和一个证伪节点；
- 预期证据类型、来源优先级、时效要求和关闭条件；
- 框架适用范围、已知盲区和需要行业专家判断之处。

框架用于决定先查什么，不预写草稿的问题数量或结论。读稿后发现框架之外的有效问题时必须保留，并标记为 `outside_framework`；不能为了提高框架利用率而强行映射。

## 第二阶段：重构命题，而不是立即挑错

阅读草稿后，先用中性语言回答：

1. 文章真正要改变谁的什么决策？
2. 一句话核心命题是什么，适用主体、地域、时点和场景是什么？
3. 哪些句子是事实、计算、推断、预测、判断或建议？
4. 作者的差异化判断是什么，它与基准或常识的差异是否有证据？
5. 结论通过哪些变量和机制传导，哪一个箭头最脆弱？
6. 什么可观察结果会使核心命题不成立？

如同时提供选题、初稿、修订稿或来源包，另做选题—成稿一致性检查，区分证据驱动变化、传播驱动变化和丢失的不确定性。

## 第三阶段：完整发现，不预设问题数量

至少完成两遍相互补充的审阅。

### A. 显性与内部一致性遍历

- 把数字、引语、政策、纪录、比较、因果、预测、动机和行动建议拆成可独立核验的最小主张；
- 保留原文精确锚点，不扩写、不润色、不把相邻句拼成作者没有说过的话；
- 检查同一主体、项目、指标、单位、分期和时间在全文不同位置是否一致；
- 复算百分比、百分点、倍数、总分关系和可由正文完成的推导；
- 区分规划与实际、总量与分期、最大值与标准值、存量与流量、平均与个案；
- 标出来源占位、失效链接、搜索摘要、模糊机构名或一个来源包打多项主张的情况。

每个锚点在进入技术台账前必须能在原稿中逐字回查；找不到原文的“引语”不得作为问题锚点。概括性问题应明确标为审阅者概括，不能加引号冒充原话。

### B. 潜在机制与行业边界遍历

- 使用公开问题先验检查参与方激励、项目落地方式、空间适配、政策效力、市场口径、服务交付、现金流、产业联系和复制条件；
- 对每个强结论列出至少一个替代解释，并判断哪类证据能区分它们；
- 把“来源缺失”“来源存在但范围不匹配”“证据冲突”和“需要专家机制判断”分开；
- 识别正文看不出的 `T2 trigger_only` 和 `T3 latent` 问题，但不把行业启发式写成已证事实；
- 为可能推翻主旨或误导行动的发现单独建立原子记录，不让文风问题淹没它们。

完整技术问题台账没有预设条数上限。仍应合并真正重复的问题，不为增加数量拆分没有独立证据路径的语法片段。面向用户的主报告只展开最多八项真正影响发布的事项：后台 `publication_effect` 为 `revise_before_publish` 或 `block_publication` 的问题必须映射，`advisory` 可以映射，`none` 不得映射。前台零项时把固定句“本稿没有仍需在发布前处理的问题。”作为独立完整行输出；否定、引语或长句中的子串不算。“展示上限”不等于“发现上限”；其余有效问题必须保留在技术台账中。

## 第四阶段：默认联网完成关键事实核验

若网络工具可用且用户未明确要求离线，主动核验会改变核心命题、发布决定或行动建议的关键主张。按风险和信息价值排序，不需要让所有低影响文风建议都消耗检索预算。

### 来源优先级

1. 适用的正式政策、法规、主管机关文件、统计数据、交易或审批文件；
2. 项目、企业、发行人或运营主体的原始披露，并明确它只能直接证明披露者作出了什么陈述；
3. 有方法说明、样本边界和日期的专业数据库或研究报告；
4. 可追溯到原始材料的高质量二手来源；
5. 新闻转载、聚合页、社交内容和搜索摘要只作为发现线索，不直接关闭重要问题。

“官方”不自动等于充分：营销稿可能证明项目方曾如此表述，却不能单独证明预测实现、因果成立或模式可复制。

### 每项外部主张的核验动作

1. 先写清最小主张和所需证据，不做漫无目的搜索。
2. 搜索并打开原始页面、正式附件或可定位文档；不要把搜索结果摘要当证据。
3. 记录发布者、标题、URL、发布日期、抓取日期和精确定位。
4. 逐项对齐主体、辖区、项目分期、指标定义、单位、时间和样本。
5. 检查来源是否过期、已替代、只有规划/预测口径，或者来自同一底层数据。
6. 对 R3、关键 R2、强标题、因果或纪录主张主动寻找冲突来源、反例或更新版本。
7. 将结果标为 `supported`、`partially_supported`、`derived`、`contradicted`、`conflicting`、`stale`、`missing` 或 `not_verifiable`，并写明来源支持到哪里为止。

这些状态不等价于发布许可。任何要求外部证据的主张，无论重要性是 core、important 还是 supporting，只有以 `supported` 引用针对该主张且范围匹配的直接外部证据，或以 `derived` 引用带同一主张目标外部血缘且通过安全复算的计算证据，才可支持 `ready`。没有有效路线时必须保留未决理由和下一步，关联至少一个尚未有效关闭的问题，并阻止 `ready`；随后再修改、缩窄、删除或暂停相应主张。

发现网页或 URL 只是 `DiscoveryHit`。候选记录至少要有唯一 ID、所服务的真实问题、发现渠道、候选定位、带时区的采集时间、来源角色和晋升状态。只有审阅流程记录已查看原始内容和可复现定位，并完成范围、时效、权利和独立性检查后，才能把候选晋升为 `EvidenceItem`。公开证据 URL 还必须通过 HTTP(S)、主机、端口、转义和凭据的基本语法检查；任意主机上 `/search`、`/web` 或 `/s` 配常见查询参数的页面，以及其他已识别搜索服务结果页，只能留在发现层。每项正式证据都必须有非空 `fit_target_refs`，只绑定实际存在的 `claim:<id>` 或 `viewpoint:<id>`；无明确目标或尚未晋升的候选继续留在 `discovery_hits`，不得提前放入 `evidence_records`。私有先验、公开先验、会议说法和审阅批注均不能跳过这一步。技术台账中的 `opened_pages`、fit、目标绑定与页面角色仍是调用方记录；当前校验器只做结构与交叉约束，不读取浏览器历史，也不证明来源语义、目标绑定合理或页面真实。URL 和搜索页识别是有限的机械下限，既不穷尽页面角色，也不证明通过者为真实原始来源。

### 联网停止条件

不要用固定搜索次数假装完成度。满足以下条件后可以停止本轮公开检索：

- 决定核心命题和发布判断的主张都有明确证据状态；
- 未关闭的 R3 已找到当前权威来源、冲突来源，或已明确记录为什么不可验证；
- 会改变行动建议的政策、数字、引语和项目边界已完成来源—主张对齐；
- 新增来源开始重复现有信息，且没有继续查找会改变结论的具体理由；
- 剩余问题只能由付费/私有材料、现场经营数据或专家判断关闭。

网络不可用、页面不可访问或预算不足时，不得假装已经联网核验。保留问题、说明已尝试的路线和剩余证据缺口，并相应收窄结论。

## 第五阶段：形成可关闭的完整技术记录

技术记录至少包含 [输出契约](output-contract.md)要求的用户材料回执、主张台账、问题台账、证据对象、验证动作和关闭决定，并使用其中的 v1.2 审阅包 envelope。`supplied_inputs`、`claim_register`、`discovery_hits`、`verification_actions`、`closure_decisions`、`evidence_records`、`issues` 和 `new_viewpoints` 必须显式存在；即使某类记录为空，也不能省略该技术层。除标准字段外，公开全证据模式应记录：

- `draft_sha256` 与审阅范围；
- `framework_timing`、`precommit_possible` 和框架适用边界；
- 原稿精确锚点或明确的审阅者概括；
- 发现来源、所用公开先验主题和是否属于框架外发现；
- 证据状态、直接支持范围、限制、反证和剩余不确定性；
- 当前工作流状态、建议处置、关闭条件、人工复核角色和重开条件；
- 实际使用的 URL、页面日期和抓取日期；
- Skill 版本、提交号或可回查安装来源、九个公开必读资源的真实文件哈希，以及网络可用性、调用方记录的检索次数、已打开页面和停止原因；
- 用户提供材料的 `supplied_inputs` 清单，其中 `input_id` 使用稳定、非路径式标识；校验时逐个通过 `--supplied-input ID=PATH` 读取真实字节所得的哈希核对结果；
- 每条发现线索的最小字段、晋升状态，以及每项正式证据非空且指向具体主张或观点的 `fit_target_refs`；
- 派生结果的来源证据、具名操作数、受限算术表达式、安全复算结果，以及各操作数对结果的可检测影响；
- 派生主张正文可见的 `derived_result` 与唯一 `calculation_evidence_ref`，并保持该结果在原文锚点、原子主张和计算结果之间的数值及百分号一致；
- 由 `publication_effect` 决定的前台事项映射，以及位置、问题、原因和处理动作四个逐字交叉锚点；
- 计划 token 区间、实际宿主 usage（若宿主提供）、外部调用和人工依赖，彼此分栏。

不要因为用户主报告篇幅有限而删除有效记录。若无法保存单独文件，在回答末尾提供“完整技术台账”附件或可复制结构；仍须让主报告保持可读。

交付前运行 `python scripts/validate_review_bundle.py <draft.md> <ledger.json> <report.md> [--supplied-input ID=PATH ...]`。技术台账声明了用户提供材料时，每个稳定、非路径式 ID 都必须绑定真实文件；仅自报哈希不能通过。单个审阅包最多 200 项正式证据，递归计算血缘最多 64 层；超过上限应拆分运行。命令行从原始 JSON 解析时还会拒绝重复对象键，必填结构出现类型错配也失败关闭。校验失败时修正运行记录或保留为未通过，不能把失败结果描述成完整模式。校验器会检查基本 URL 语法，排除 `/search|/web|/s` 配常见查询参数及其他已识别搜索结果页，阻止正文自证外部问题，拒绝未绑定的用户材料、无目标证据、不一致的受限算术复算和已识别的无影响操作数，并检查验证动作、关闭决定及前后台映射；它不穷尽所有搜索服务，操作数扰动也不是完整符号依赖证明。它不证明网页或材料真实、操作数摘录正确、fit/目标绑定/人工复核声明属实、前后台语义等价，或模型已经发现全部行业问题。

关闭问题时，`closure_evidence_refs` 必须由所引验证动作的证据并集完整覆盖，并与关闭决定的证据集合一致；验证动作时间不得晚于关闭决定。若动作或决定所引证据直接或经计算血缘使用用户材料，两类时间都不得早于对应材料的 `captured_at`。关闭证据还须逐项覆盖问题关联的每条主张：要求外部证据的主张逐条获得同目标且范围匹配的外部来源或同目标外部血缘计算。若问题以 `derived` 关闭，全部关联主张都必须是 `derived`，且各自主张指定的 `calculation_evidence_ref` 均位于关闭证据中。旧快照上自报 `revised`、`deleted` 或 `narrowed` 不能关闭问题；先保存修改后的新草稿快照，重算哈希和主张台账，再运行一轮审阅。上述时间字段是调用方记录，只形成台账时序下限，不认证真实采集或执行过程。

## 第六阶段：只在证据足够时提出零至两条新观点

新观点不是标题改写、原稿摘要或为了显示能力而增加的评论。每条候选在后台必须有唯一 `viewpoint_id`，在前台固定包含以下五个标签：

1. **适用对象**：明确哪个参与方会采取行动或承担后果；
2. **决策问题**：明确这条观点会改变什么选择；
3. **可能机制**：指出原稿没有展开的变量、传导链、替代解释或情景分叉；
4. **适用边界**：限定地区、园区类型、产业、项目阶段或时间；
5. **反证条件**：给出可观察的反例、阈值或未来数据。

五个标签的值都必须是实质说明，后台 `actor`、`decision`、`mechanism`、`boundary`、`falsifier` 的完整文字须逐字、且不被有限词表中的明显否定前缀直接否定地出现在各自对应的标签值中。完整 `mechanism` 字段不得逐字复制草稿。证据基础和剩余不确定性继续保留在技术台账；逐字绑定、有限否定和复制检查只形成保守的机械下限，不证明前后台语义等价、观点得到语义支持或真正新颖。

证据基础中至少一项必须是范围匹配的外部来源，或带范围匹配外部血缘且已安全复算的派生结果；观点引用的每项证据都必须绑定 `viewpoint:<viewpoint_id>`。`draft_internal`、公开先验、私有先验和知识卡不能单独支撑新观点。

若不能同时满足以上条件，把“本稿暂不足以形成可靠的新观点。”作为独立完整行输出，而不是凑满两条；否定、引语或长句中的子串不算。公开先验只能帮助提出问题，不能成为新观点的证据。

## 第七阶段：两层交付

### 面向用户的中文报告

遵循 [用户可读报告](user-facing-report.md)：把“可以发布。”“修改后发布。”或“暂缓发布。”之一作为完整首句，再说明做得好的地方、最重要的发布前问题、修改顺序、新观点、剩余验证和本次限制。七个固定二级章节都要有实质正文；三级标题只用于问题和新观点事项，普通章节不得使用。校验器会拦截一组常见的明显冲突词，但不能证明整份结论语义一致。不得向第一次使用 Skill 的读者展示 `R2`、`V3`、对象 ID 或机器字段来代替自然语言解释。

每个重点问题都回答：

- 原文在哪里；
- 本次证据支持到哪里；
- 为什么会影响事实、推理、决策或发布；
- 最小处理动作是什么；
- 处理后还剩什么不确定性。

### 完整技术台账

单独保存全部主张、问题、来源、验证动作、关闭条件和框架血缘。主报告的八项上限只控制读者负担，不限制台账发现；单个审阅包的正式证据仍受 200 项机械上限约束，超出时须拆分。每个前台事项都必须由至少一个后台问题通过序号和四个逐字摘录绑定；四个前台出现处不得被有限词表中的明显否定前缀直接否定。若主报告合并了同类项，每个被合并问题仍须独立回查并说明合并理由。该绑定与否定检查只证明若干词面条件，不证明两层叙述语义等价。

## 与私有知识层的关系

公开全证据模式不依赖私有知识即可运行。若用户另有授权的 Knowledge Cards、会议内容或审改经验：

- 先按 [Knowledge-prior workflow](knowledge-prior-workflow.md)和 [私有经验来源与支持数据](private-experience-provenance.md)建立冻结先验与支持关系；
- 私有材料只增强问题选择、边界和取证路线，不自动提高目标文章事实的证据等级；
- 不把私有文件名、人物、路径、原话或可识别片段写进公开报告或公开仓库；
- 只有满足 `IRA-ABCDEF-V1.1` 的全部固定条件时，才把运行标为正式 F 组。

因此，对外可以准确描述为：“安装后默认获得公开 F-style 全证据审阅；接入经授权的私有先验与支持层后，可以在受控协议中运行正式 D/F 评测。”不要描述为“下载后获得某位导师的全部经验”或“模型已经被行业知识训练”。

## 失败与降级规则

- **无网络**：完成框架、命题、内部一致性与证据缺口审阅；所有动态或外部主张保持未验证。
- **缺原始来源**：不把来源缺失改写成事实错误；给出所需来源和可执行核验路线。
- **来源冲突**：保留冲突、说明范围和时点差异，交人工决定；不静默选择最符合原稿的一条。
- **只能靠专家关闭**：列出事实层、推断层、替代解释和专家需要回答的问题，不冒充专家结论。
- **严格 precommit 不可能**：保留生产审阅价值，但把时间边界标为回溯，不做因果效果声明。
- **证据不足以产生新观点**：输出零条并说明不足，不用泛泛建议填充。
- **R2 或 R3 未关闭**：总体结论不得为 `ready`；未关闭的 R2 必须标为发布前修改或阻断，未关闭的 R3 必须标为阻断发布并使总体状态为 `hold`，前台完整首句使用“暂缓发布。”。
- **任一外部主张没有有效路线**：无论其重要性等级，保留未决原因、下一步和关联的活动问题，并阻止 `ready`。
