# ABCDEF-v1.1 因子评估协议

协议 ID：`IRA-ABCDEF-V1.1`。本协议与历史 `ABC-v1.0` 分开记录；不同测试集、知识快照或协议 ID 的分数不得直接拼接。

## 组别

| 组 | 公开审阅规则 | 私有经验问题 | 来源/支持 sidecar | 读稿前结构化框架 |
|---|---|---|---|---|
| A | 否 | 否 | 否 | 否 |
| B | 是 | 否 | 否 | 否 |
| C | 是 | 是 | 否 | 否 |
| D | 是 | 与 C 完全相同 | 是 | 否 |
| E | 是 | 与 C 完全相同 | 否 | 是 |
| F | 是 | 与 C 完全相同 | 与 D 完全相同 | 是 |

C/D 共用同一个已经冻结的 `PriorQuestionManifest`；E/F 在读取草稿前把同一批问题综合为 `ReadingFrameworkManifest`。因此框架因子是“结构化综合”，不是第一次让知识先于草稿出现。

## 可识别比较

- `D - C`：来源与支持信息的直接效应；
- `F - E`：在框架存在时的支持信息效应；
- `E - C`：无支持信息时的框架综合效应；
- `F - D`：有支持信息时的框架综合效应；
- `F - E - D + C`：两种因素的交互。

D 不一定提高召回；若它减少错误证据晋升、改善不确定性表达和关闭路径，也属于真实增量。E/F 若只增加长度和误报，不提高潜在问题、命题结构或证伪质量，就不能描述为有效。

## 固定条件

同一案例的六组必须使用相同草稿字节、公开来源包、Skill 版本、模型与推理档位、联网设置、最大输出、运行次数和输出契约。C/D/E/F 的固定执行条件写成同一个 `execution_configuration_hash`；该 hash 覆盖模型、推理档位、上下文与输出上限、联网和工具策略、重试规则、输出契约，但不包含刻意变化的支持包与阅读框架。每个案例还要声明各组相同的正整数 `run_count`。

模型宿主实际返回的 token 只能写在 `reported_token_usage`，并标为 `caller_reported`；外部调用数与人工复核分钟只能写在 `reported_operational_costs`。未提供的字段保留缺失，不得根据字符数、文件字节或其他 token 字段补算。字符预算和预估 token 可以单独报告，但不能混入实测成本字段。

框架生成阶段物理隔离草稿与 gold。支持数据不得包含测试稿、同一版本链、该稿批注、修订稿、近似改写或由这些材料传递派生的卡片。无法证明来源独立时，从正式盲测中排除。

## 核心指标

沿用问题召回、误报、R/T/V 对齐、理由质量、可关闭性、命题保真和成本，并新增：

- 经验来源覆盖率、locator 可复现率、来源角色准确率；
- 错误证据晋升数、反证保留率、来源与隐私泄漏数；
- 框架前置有效率、变量与参与方覆盖率、框架利用率；
- 框架外有效发现率、框架诱发误报率、证伪与替代解释质量。

所有指标先按案例配对，再汇总主效应和交互。小样本报告方向与区间，不做总体显著性或准确率宣传。

## 指标定义与可比边界

每个数值指标必须预先登记：

- `metric_class`：`common_outcome` 或 `group_process`；
- `direction`：`higher_is_better`、`lower_is_better` 或 `descriptive`；
- `range.minimum/maximum`：至少一端有限，超出范围即拒绝评分；
- `applicable_groups`：指标真正适用的组。

共同 outcome 必须适用于 C/D/E/F，才可计算完整主效应和交互。组专属 process 指标只在定义允许的组间计算对比：例如 D/F 的来源角色准确率可计算 `F-D`，但不能伪造包含 C/E 的支持主效应；E/F 的框架结构分可计算 `F-E`，但不适用于 C/D 的比较。不适用显示为 `applicable: false`，不能写成缺失、0 或负面表现。

`score_factorial_eval.py` 的最小算术边界是：输入值已经是案例×组的运行汇总；脚本先计算同一案例内完整配对差，再对案例做不加权算术平均。它不汇总底层重复运行、不按文章长度加权、不自动做 bootstrap 或显著性检验，也不把协议对比描述为超出设计范围的因果效应。

## 评分产物的隐私与写入

全合成公开夹具必须同时声明 `fixture: fully_synthetic` 和 `data_classification: public_synthetic_no_private_content`。其他输入一律视为真实/私有评测：必须指定仓库外或 `.gitignore` 已排除目录中的输出，标准输出和错误输出不得出现 evaluation ID、case ID 或绝对路径。

真实评测默认只保留稳定的 `case_ordinal`，不把逐案例 ID 写入评分产物。确需在安全私有产物中回查时，显式使用 `--include-private-case-ids`。输出文件默认拒绝覆盖；`--allow-identical-existing` 只允许已有文件与本次结果逐字节相同时幂等成功，不会重写文件。

## 发布声明

全合成案例只能证明工程不变量和开发回归。只有在 Skill、知识和协议冻结后取得的新稿上完成隔离盲测与人工裁决，才可陈述该测试范围内的行为增量。不得声称“模型已学习公司知识”“复刻特定导师”或“自动证明文章正确”。
