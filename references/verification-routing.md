# 验证难度与双轴路由

## 使用目的

本文件规定产业研究审阅发现如何同时标注用户风险和验证难度，并据此选择证据与复核人。用户风险使用 `R1`、`R2`、`R3`；验证难度使用 `V1`、`V2`、`V3`。

两轴回答不同问题：

- `R` 轴：若问题不处理，会多大程度影响读者理解、用户决策、合规或声誉？
- `V` 轴：要可靠关闭问题，最低需要什么证据、语境和专业能力？

不得从一个轴推导另一个轴。`R3` 不自动等于 `V3`，`V3` 也不自动等于 `R3`。

## 用户风险路由

| 等级 | 判断标准 | 发布规则 |
| --- | --- | --- |
| `R1` | 局部表达、语气或清晰度问题，不改变主要事实和决策 | 可接受或改写，记录处理结果 |
| `R2` | 可能明显改变读者理解、比较结果、对象边界或公平性 | 必须经人工决定并记录理由 |
| `R3` | 可能推翻核心结论、误导行动、造成重大合规或声誉风险 | 关闭前不得发布 |

风险级别取决于该问题在当前文章中的作用，不取决于核验耗时、来源数量或审阅者资历。

## V1 基础显性核验

`V1` 适用于能够通过正文、直接来源、正式名称、数字台账或版本比对解决的问题。

常见信号：

- 正文与来源中的名称、日期、单位或数字不一致
- 当前状态被写成历史变化，但缺少基期
- 绝对量词、纪录或趋势词没有相应样本和统计期
- 比较双方的指标、单位或时间显性不同
- 信息重复、提示背景外泄或模板化表达不增加含义

最低证据：准确锚点、包含上下文、直接来源、来源日期和必要的计算或版本差异。

处理路由：先用确定性检查或资料比对。若证据能直接覆盖主张，可提出关闭建议；`R2` 或 `R3` 仍由人工确认。文风类发现即使容易识别，也不得自动判定作者使用了 AI。

## V2 语境利益相关方与政策意图核验

`V2` 适用于只有补齐发表语境、目标读者、利益相关方、辖区或政策时点后才能判断的问题。

常见信号：

- 标题或结论对某类地区、机构或企业预设失败、欺骗或动机
- 用词选择服务于读者定位或品牌声音，而不是事实正误
- 文本对许可、备案、优惠、支持或政府行为作出行动判断
- 当前政策环境、发布渠道或观察窗口决定一句话是否成立
- 比较本身数据可得，但是否值得比较取决于文章目的

最低证据：`target_reader`、`publication_context`、`stakeholder_map`、`jurisdiction`、`effective_date`、当前权威政策来源及其适用对象。

处理路由：由研究人员补齐语境和现行来源，再交编辑、政策负责人或相应专业人员关闭。工具只能指出待核验的法源、辖区、时点和利益相关方，不得从敏感关键词直接推出允许、禁止或违法。

## V3 行业隐性知识与专家判断

`V3` 适用于争议涉及行业惯例、产品机制、商业模式、资产质量、风险分担或多因素因果链的问题。

常见信号：

- 从单个经营指标直接推断整体质量或市场态度
- 把多因素结果归因于某个项目、主体或唯一原因
- 将“市场”“资本”或“行业”写成具有统一意图的行动者
- 核心结论依赖“通常如此”“行业惯例”或未展开的交易机制
- 不同指标给出相反信号，文章却只保留一个解释
- 导师或审阅者提出多个替代原因，而非要求补一个公开数字

最低证据：机制说明、同类案例、跨期或对照资料、替代假设、专家角色与判断理由。仅有职位、资历或一句“业内普遍认为”不构成关闭证据。

处理路由：模型先列出事实层、推断层、替代解释和缺口，再升级具备相关经验的复核者。没有足够机制证据时，输出应是待验证假设或研究问题，不应自动生成更确定的新结论。

## 原子问题拆分

一条批注可能同时包含名称纠错、受众风险和行业判断。按以下方式拆分：

1. 为每个能够独立补证、改写或接受的问题建立单独记录。
2. 给每条记录保留同一批注来源，但使用不同的 `atomic_issue_id`。
3. 分别赋予 `category`、`risk_level` 和 `verification_level`。
4. 分别记录证据、复核人和关闭状态；不得用其中一项的证据关闭其他项。

例如，完全虚构的一条审阅意见可能同时指出：设施正式名称写错、标题会误导当地读者、作者对行业瓶颈的判断缺少依据。它应拆成 `V1` 名称核验、`V2` 受众核验和 `V3` 行业判断，而不是整条统一标成 `V3`。

## 九宫格示例

以下情形完全合成，仅说明两轴组合：

| 组合 | 合成示例 |
| --- | --- |
| `R1/V1` | 一段背景重复前文，删除后不影响事实或论证 |
| `R1/V2` | 两个均可接受的行业称呼中，哪一个更符合目标读者需要编辑判断 |
| `R1/V3` | 某个非核心工艺阶段的业内简称存在分歧，需要专家确认但不影响结论 |
| `R2/V1` | 图表遗漏统计期，使读者可能误读比较结果 |
| `R2/V2` | 标题对一类公共机构作出不公平预设，需要结合受众和发表场景判断 |
| `R2/V3` | 非核心段落把一种商业模式称为行业主要瓶颈，但缺少同类案例和机制依据 |
| `R3/V1` | 决定全文结论的关键值与直接来源不一致 |
| `R3/V2` | 文章依据未经核验的许可解释向读者提出可执行建议 |
| `R3/V3` | 核心决策建议建立在未经证实的单一行业机制上，并忽略相反指标 |

## 输出字段

每条原子发现至少输出：

```text
atomic_issue_id
category
risk_level
verification_level
level_basis
anchor
context
claim
required_evidence
required_reviewer
recommended_action
can_auto_close
source_freshness
alternative_hypotheses
human_status
```

`can_auto_close` 只表示是否存在确定性证据路径，不授权工具自行发布、删除材料或替代人工批准。

## 路由约束

- 不因问题很显眼就将验证难度设为 `V1`；难度取决于关闭所需证据。
- 不因需要专家就提高 R 级；风险取决于对用户的影响。
- 不把政策关键词当成政策结论，也不把导师偏好的改写固化成禁用词或替换表。
- 不以流畅改写代替补证，不以“专家认为”代替机制和依据。
- `R3/V3` 无法及时关闭时，应保留为未解决问题或删除相关主张，不得弱化标签后继续发布。
