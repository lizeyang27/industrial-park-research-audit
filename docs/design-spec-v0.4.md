# 行业研究文章审阅 Skill 设计说明 v0.4

> 状态：设计基线。本文描述目标架构、控制边界和分阶段实现顺序；其中部分模块尚未编码。真实文章、导师批注和内部知识仅用于私有评估，不进入公开仓库。

## 1. 设计目标

这个 Skill 不是自动润色器，而是一个面向中文产业研究稿的“研究质量控制系统”。它回答两个彼此相关但不能混为一谈的问题：

1. **推理审计**：文章中的重要主张是什么，哪里可能存在事实、口径、范围、比较、因果、政策、行业机制或发表风险，下一步应如何核验和关闭。
2. **命题重构**：去掉标题、流量、客户表达和篇幅约束后，文章真正试图回答的中性研究问题是什么，核心判断由哪些变量、证据、假设和反证条件支撑。

Skill 的目标不是“复制某位导师的措辞”，而是把人工批注背后的问题结构转化为可追踪、可测试、可人工关闭的审阅流程。

## 2. 非目标

- 不判断作者是否使用 AI，只审查模板化、冗余、证据不足却语气确定等文本风险。
- 不承诺自动事实核验。搜索、知识库命中和专家意见都不是天然成立的证据。
- 不提供法律、审计、鉴证或投资意见。
- 不根据一个案例建立永久禁词或固定替换表。
- 不推测同行作者的心理动机或真正“灵感”；只重构文章明示或可核验的证据基础。
- 默认不自动改原文、不发布、不上传私有材料，也不自动关闭高风险问题。

## 3. 对原始“四层”思路的重构

原设计把文本粒度、风险后果、发现方式、验证难度和人工边界放在同一条“由浅到深”的轴上。它能帮助形成直觉，但不能直接驱动工作流。例如关键数字抄错可能很容易发现，却会推翻全文；一个行业术语可能需要专家确认，却只影响局部表达。

保留原设计的四类观察位置，但将它们改名为**审阅粒度**，不再代表风险高低：

| 原始层次 | 新粒度 | 保留的价值 | 必须另行记录的维度 |
|---|---|---|---|
| 基础校验 | `G0 surface` | 名称、数字、日期、单位、冗余和语体 | `R`、`V`、发现通道、证据状态 |
| 句子逻辑与范围 | `G1 claim` | 原子主张、量词、范围和限定条件 | 是否只是触发信号，是否需要外部事实 |
| 高阶判断 | `G2 relation` | 比较、因果、预测、机制和替代解释 | 知识来源、验证动作、专业复核人 |
| 篇章级关系风险 | `G3 thesis` | 主旨、政策语境、利益相关方和命题漂移 | 发表后果、语境、反证和关闭权限 |

一句话可以同时命中多个粒度；粒度不决定严重度。

## 4. 六个相互独立的分类轴

### 4.1 审阅粒度 `G`

- `G0 surface`：词、数字、日期、格式、重复表达和术语表面形式。
- `G1 claim`：一个可以独立判断真伪、证据状态或适用范围的主张。
- `G2 relation`：两个或多个主张之间的比较、因果、机制、预测或行动推导。
- `G3 thesis`：标题、核心命题、受众、发表语境以及文章各部分对主旨的共同作用。

### 4.2 文本可发现性 `T`

这个轴回答“只看文字，最多能知道什么”，而不是回答问题是否真实成立。

- `T1 direct`：仅凭正文内部即可确认问题，例如前后数字冲突、同一术语不一致、无信息量重复。
- `T2 trigger_only`：文字能触发疑点，但不能证明错误，例如“普遍”“必然”“市场逼迫”“真正的企业都……”等范围、动机或单因果表达。
- `T3 latent`：正文没有稳定、可靠的触发信号；只有结合交易结构、产业规模、政策时点、读者关系或私有经验后才会出现问题候选。

`T2` 必须写成“待核问题”，不能写成“错误”。`T3` 不能靠罗列敏感词假装发现。

### 4.3 发现通道 `D`

- `D0 deterministic_text`：确定性的正文或格式检查。
- `D1 semantic_text`：模型从范围、逻辑、语气和隐含前提中形成问题候选。
- `D2 document_set`：题纲、初稿、来源、图表、批注和终稿之间的交叉或版本比对。
- `D3 private_knowledge`：经授权的私有知识卡提供机制线索、反例和应提的问题。
- `D4 context_or_human`：需要发表场景、政策责任人、利益相关方或领域专家主动提出。

一个问题可以有多个发现通道。记录首先发现它的通道，也记录用于复核的其他通道。

### 4.4 风险后果 `R`

- `R1`：局部表达或清晰度问题，不改变主要事实和决策。
- `R2`：可能明显改变读者理解、对象边界、公平性或机构声誉。
- `R3`：可能推翻核心结论、误导行动，或造成重大政策、合规与声誉风险；关闭前不得进入 ready。

### 4.5 验证难度 `V`

- `V1`：正文、直接来源、正式名称、数字台账、复算或版本比对即可关闭。
- `V2`：需补齐目标读者、发表语境、辖区、政策时点或利益相关方后判断。
- `V3`：需行业机制、同类案例、替代假设、专业知识或专家判断。

`R` 与 `V` 正交。`R3/V1` 和 `R1/V3` 都可能存在。

### 4.6 关闭路线 `C`

- `C0 edit_only`：纯表达问题，编辑确认最小改写或删除。
- `C1 direct_compare`：回到原文、附件、原始披露或版本进行逐项匹配。
- `C2 reproduce`：复算数字、公式、比例、单位或图表。
- `C3 primary_web`：联网寻找并打开当前一手或权威来源，再做范围和时效核验。
- `C4 kb_then_corroborate`：私有知识库先给问题、术语和候选来源，随后由独立材料佐证。
- `C5 context_review`：由编辑、政策或利益相关方负责人判断发表语境与可接受边界。
- `C6 domain_expert`：由具备相关机制经验的人给出理由、适用范围与替代解释。
- `C7 narrow_delete_hold`：无法在成本或时间内验证时，缩窄为假设、删除，或暂停发布。

关闭路线可以组合。例如行业机制可能先经 `C4` 找到应问的问题，再经 `C3` 取得公开材料，最后由 `C6` 判断是否足以关闭。

## 5. 核心工作流

```text
输入登记
  → 识别 topic / draft / source / review / revision
  → 提取 material claims
  → 产生 TriggerHit（问题线索）
  → 拆成 AtomicIssue（一个可独立关闭的问题）
  → 标注 G/T/D/R/V
  → 生成 DiscoveryPlan
  → 获得 DiscoveryHit（候选来源或线索）
  → 证据准入检查
  → 执行 VerificationAction
  → 形成 ClosureDecision
  → 人工确认关闭、退回、接受风险或暂停
```

### 5.1 什么必须拆成原子问题

只有在下列任一情况成立时才拆分：

- 两部分需要不同证据；
- 两部分的 `R` 或 `V` 不同；
- 一部分可以删除，另一部分必须补证；
- 一部分成立不代表另一部分成立；
- 两部分需要不同角色批准。

连接词、铺垫和不产生独立事实或推断的片段不拆。目标不是把 100 句话机械扩成 1000 项，而是找出会改变结论、证据状态或处置方式的 material claims。

### 5.2 批注如何转化为可复用能力

导师批注首先是“审阅者在某个案例中提出过什么”，不是普遍事实，也不是永久规则：

```text
真实批注
  → 私有来源记录
  → 批注意图拆解
  → 一次性 case note
  → Trigger Candidate
  → 正例、近似反例和盲测
  → Active Trigger Template
```

只有满足至少一个条件才考虑晋升：

- 两个以上独立案例指向同一种可关闭问题；
- 虽只出现一次，但对应明确的 `R3` 风险；
- 能稳定改变验证路线、证据要求或关闭角色；
- 有明确适用范围、排除条件和停用条件。

单纯措辞替换和结尾偏好通常只保留为有范围的 case note。

## 6. 发现不等于证据

系统必须使用不同对象保存线索与证据：

```text
TriggerHit ≠ DiscoveryHit ≠ EvidenceItem ≠ VerificationResult
```

- `TriggerHit`：文本、知识卡或人工观察产生的问题候选。
- `DiscoveryHit`：搜索结果、URL、知识卡命中、会议说法或可能相关的材料。
- `EvidenceItem`：已经打开原始来源、保存精确定位，并通过准入检查的材料。
- `VerificationResult`：对证据执行逐项匹配、复算、政策适用或反假设测试后的结果。

搜索摘要、一个链接、导师批注、会议发言、知识卡命中和专家资历本身都不能直接关闭外部事实。

### 6.1 证据准入门槛

候选材料晋升为 `EvidenceItem` 前至少检查：

1. 是否打开原始来源，而非仅看到摘要或二手转述。
2. 是否保存页码、章节、表格、公告编号或其他精确 locator。
3. 主体、地区、期间、定义、样本、单位、分母是否匹配。
4. 资料是否在有效期内，是否被撤回、修订或替代。
5. 来源角色、利益关系和独立性是否适合该主张。
6. 使用、存储和外部传输是否获得授权。
7. 对核心结论是否检查独立来源、冲突来源和实质反证。

## 7. 分通道解决策略

| 发现情形 | 首选路线 | 何时联网 | 何时用知识库 | 何时必须人工 |
|---|---|---|---|---|
| 前后矛盾、重复、正式名称不一致 | `C0/C1` | 本地资料没有正式来源时 | 可提供术语别名，不作证据 | `R2/R3` 最终确认 |
| 数字、日期、比例、单位 | `C1/C2` | 缺原始披露或需确认当前值时 | 可提供来源位置线索 | 关键值影响结论时 |
| “普遍”“全部”“首次”等量词 | `C1/C3` | 需要样本全集或当前记录时 | 可提醒样本边界 | 样本代表性判断 |
| 政策、政府意图、允许或禁止 | `C3/C5` | 默认需要核对现行权威法源 | 仅提供辖区、旧版本和检索词 | 政策或法律责任人 |
| 标题可能冒犯地区、机构或企业 | `C5` | 需要了解当前争议或公开语境时 | 可保存历史误读模式 | 编辑/品牌/利益相关方负责人 |
| 单因果、市场动机、行业惯例 | `C4/C6` | 有可观察数据或同类案例时 | 用于提出替代假设和机制问题 | 行业专家关闭 |
| 正文看不出的项目规模或交易结构 | `C4/C6`，必要时 `C3` | 需核实具体项目、规则或现状时 | 适合提供隐性机制和反例 | 领域专家关闭 |
| 暂时无法验证的重要主张 | `C7` | 只有授权且成本合理时继续 | 命中也不能强行关闭 | 作者/主编决定缩窄、删除或 hold |

联网不是默认答案。先判断缺口究竟是“缺一手事实”“缺政策适用”“缺行业机制”还是“缺发表决策”；不同缺口需要不同的关闭人。

## 8. 最小数据模型

### 8.1 `ReviewRun`

记录：输入文件 ID 与哈希、Skill 与 Schema 版本、研究问题、目标读者、发表场景、辖区、`as_of`、允许的发现通道、授权引用、处理环境和输出对象。

### 8.2 `TriggerHit`

记录：触发模板、来源批注引用、锚点与上下文、触发理由、适用性检查、置信度，以及 `candidate/dismissed/promoted`。

### 8.3 `AtomicIssue`

记录：关联主张、原子问题、风险类型、`G/T/D/R/V`、影响路径、隐藏前提、替代假设、所需证据、所需复核角色和当前流程状态。

### 8.4 `DiscoveryPlan`

记录：发现通道、授权、预期来源类型、停止条件、预计成本、外部调用和执行状态。

### 8.5 `EvidenceItem`

记录：来源角色、发行或发布主体、locator、采集时间、一手或二手、直接性、独立性、时效性、范围适配、权限、局限和准入结论。

### 8.6 `VerificationAction`

动作至少包括：`exact_compare`、`recalculate`、`definition_match`、`scope_match`、`temporal_check`、`policy_applicability`、`independence_check`、`counterhypothesis_test`、`expert_review`。

### 8.7 `ClosureDecision`

记录：关闭条件逐项结果、处置结论、修订动作、准入证据 ID、复核角色、复核时间、剩余限制、有效期和重开条件。

## 9. 状态机和关闭规则

```text
CANDIDATE
  → ATOMIZED
  → TRIAGED
  → ROUTED
  → DISCOVERING
  → VERIFYING
  → DECISION_READY
  → HUMAN_REVIEW
  → CLOSED / BLOCKED / 返回 VERIFYING
```

流程状态、处置方式和发表影响必须分开记录：

- `workflow_state`：问题走到哪一步。
- `disposition`：修订、补证、误报、接受风险、删除、无法验证等处理结论。
- `publication_effect`：none、advisory、revise_before_publish、block_publication。

以下情况不能直接等同于关闭：`revised`、`evidence_added`、`unverifiable`、搜索到 URL、命中知识卡或收到专家一句意见。未解决的 `R3` 即使标记为接受风险，也不能让总体状态变成 `ready`。

已经关闭的问题遇到以下事件必须重开：

- 主张文本、数字、范围或文件版本改变；
- 证据过期、撤回、被替代或权限撤销；
- 出现冲突来源或新的实质反证；
- 动态政策、市场或公司事实跨过有效期。

## 10. 私有知识库设计

### 10.1 可以放什么

- `fact_evidence`：可回到原始来源的事实材料。
- `reported_statement`：会议或访谈中某人表达过的观点。
- `expert_heuristic`：行业经验、反例、问题模板和路由提示。
- `control_rule`：证据准入、权限、关闭和升级规则。

### 10.2 不同卡片的权限

- 事实卡可以成为候选证据，但仍需检查时效、范围和独立性。
- 会议说法只能证明“有人这样表达过”，不能自动证明外部事实。
- 导师批注和专家启发式只能产生问题、替代解释或验证路线，不能填入事实证据字段。
- 控制规则可以约束流程，但不能证明行业命题。

### 10.3 知识卡最低字段

来源、内容类型、主体、行业、地区、阶段、期间、定义、适用条件、排除条件、原始 locator、核验日期、有效期、权限、允许用途、独立来源、冲突来源、替代关系和生命周期。

### 10.4 权限与生命周期

每次检索声明 `purpose + processor_class + output_audience`。授权清单需要记录有效、到期、撤销和允许的处理环境。卡片经历 `draft → pilot → active → deprecated`；动态、冲突、过期或撤权卡只返回刷新或阻断提示。

知识库可以很大，但运行时不应把整本书或全部会议内容塞进提示词。原始材料保留在私有库中，经过分段、元数据和权限管理后按问题检索；运行时只取最少必要片段。另建知识卡是为了路由和压缩，不替代原始材料。

## 11. 命题重构模式

重构不从标题直接猜“作者想法”，而是依次输出：

1. 中性研究问题。
2. 文中可确认的事实基线。
3. 作者的核心命题与适用范围。
4. 相对市场共识或当前基准的不同判断；没有证据时写“尚未建立”。
5. 驱动变量、代理指标、方向、时滞和证据状态。
6. 从产业变量到销量、价格、成本、利润、现金流、资本开支、资产价值或融资条件的传导链。
7. 替代解释、场景和可证伪条件。
8. 文章标题或传播叙事造成的确定性放大、对象扩大或命题漂移。
9. 当前仍缺的材料和决策相关数据。

## 12. 分阶段成本与用户决策点

### 阶段 A：本地结构化审阅

完成文件角色识别、material claims、`D0/D1/D2`、全部 `V1` 候选、问题去重与优先级。默认不联网。

### 阶段 B：语境与当前来源核验

只处理用户选定的 `V2`。报告预计需要的权威来源、联网次数、token 增量和政策或编辑依赖。

### 阶段 C：行业机制与专家核验

只处理用户选定的 `V3`。先检索获授权知识库，再列需要的机制材料、反例和专家问题；更多 token 不能替代专家。

每个阶段结束后给出停止点：接受当前限制、只继续选定问题，或升级更深验证。token 只能给宽区间规划值，并写明字符数、主张数、来源数、知识卡数和外部调用等假设；不承诺实际计费。

## 13. 输出契约

正式输出至少包括：

- 总体状态与已完成范围；
- 主张台账；
- 问题台账；
- 发现计划及候选来源；
- 准入证据与验证动作；
- 人工关闭记录；
- `V2/V3` 增量成本和用户决策点；
- 若启用命题重构，增加研究命题卡与选题—成稿一致性。

每条问题都必须能回答：在哪里、是什么风险、为什么只是候选或为何已成立、用什么材料验证、谁来关闭、什么条件下重开。

## 14. 评估与防过拟合

测试集分为开发案例、全合成盲测、无问题近似反例和私有专家案例。真实批注只在私有环境中作为有限参照，且人工批注不是完整真值集。

评价至少包括：重要问题召回、误报、`R/V` 一致性、理由质量、可关闭性、命题保真、抗标题漂移、问题去重和成本控制。单个案例不得直接形成永久禁用词；每个活跃触发器都要有适用条件、排除条件、正例、近似反例和退役条件。

## 15. 隐私与发布边界

- 默认本地处理，外部搜索只提交最少必要的抽象问题。
- 真实批注、内部题纲、会议记录、数据库导出、本地路径和人物身份不进入公开仓库。
- 公开示例必须完全合成，不能只做轻度改名。
- 每次外部处理记录授权目的、处理环境和输出对象。
- 发布前运行隐私预检；公开 Skill 与私有知识库物理隔离。

## 16. 实现路线

### M0：设计和私有分类

- 将真实批注拆为原子意图，建立 `G/T/D/R/V/C` 私有分类表。
- 对有前后版本的文章记录 closed、partial、open/unknown，而不是把“文字变了”视为验证成功。

### M1：本地 V1 闭环

- 建立 Audit Case、Atomic Issue、状态转换和关闭校验。
- 支持 `D0/D1/D2`；不接联网和私有知识库。
- 对评论混合问题、重复命中、版本变化和 `R3` 阻断编写合成测试。

### M2：知识库治理

- 实现授权清单、purpose、处理环境、有效期、撤销、范围过滤和安全 guidance 接口。
- 禁止 reviewer comment、meeting statement 和 heuristic 直接成为事实证据。

### M3：证据准入与联网

- 分离 `DiscoveryHit`、`EvidenceItem` 和 `VerificationAction`。
- 只有完成原始来源打开、locator、范围、时效、权限和独立性检查后才能进入关闭逻辑。

### M4：专家与动态重开

- 接入政策、行业专家复核角色。
- 实现动态事实有效期、证据撤回、版本变化和反证出现后的自动重开。

### M5：独立评估

- 在不泄露预期答案的环境中运行合成盲测和私有专家案例。
- 只对实际测试范围声明能力，不声称“复刻导师”或“保证正确”。

## 17. 当前版本的完成定义

v0.4 视为“设计基线完成”，不视为产品完成。进入下一版前应满足：

- 每条私有导师批注至少形成一个可追踪问题；混合批注已拆分。
- 所有问题都有 `T/D/R/V/C` 和人工关闭角色。
- 文本线索、知识库线索、联网候选、准入证据和关闭决定不再混用。
- 公开文档不含真实雇主材料和导师原话。
- 当前代码能力与计划能力在 README 中明确分开。
